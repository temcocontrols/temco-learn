Temco's T3000 documentation did not start with this site. It started with two printed manuals that shipped with the DOS-era T3000 software, and with a folder of support documents that were never in print at all. Those originals still live in the source repository under `T3000_CrossPlatform/Documentation`, and this project is what became of them.

## What is here, and how much to trust it

| Document | Pages | Treatment |
| --- | --- | --- |
| T3000 Installation and Technical Manual | 50 | Converted in full — the pages in this project are the manual, reflowed |
| T3000 Software Manual | 117 | Outline only — the text could not be recovered cleanly, see [why](software-manual-text-defect.md) |
| Flashing a Raspberry Pi Compute Module | 11 | Converted in full |
| Backing up a Raspberry Pi Compute Module | 4 | Converted in full |
| T3-BB top and bottom schematics | 2 sheets | Described, with the sheets linked in the source repository |

Everything converted here was taken from the PDFs word for word. Nothing was rewritten from memory, and where a figure could not be carried across, the caption is still in place so you can see what was there and go back to the PDF for it.

## Why these are kept

The technical manual answers questions the current product documentation does not: how the T3000 panel is physically assembled, what the DAQ, connector and netcards do, how the MINI 64 and MINI 16 were wired, and how a panel is addressed on a network. The Raspberry Pi documents describe how a Compute Module is flashed and how a configured image is backed up and shrunk — still the procedure for the T3 Router.

The manuals describe hardware that Temco no longer ships, so read them as history. For anything current, read the T3000 manual project on this site instead.

`DosT3SoftwareManual.PDF` is a 117-page manual whose text layer is unusable. Every word of more than one syllable was typeset with a space inside it — sometimes two. This is in the PDF itself, not in one extractor: `pypdf` and PyMuPDF produce the same text, and both describe roughly 38,000 words against a document that reads as about 25,000.

A paragraph from page 6, exactly as it extracts:

```
The T3000 sys tem is a com plete En ergy Man age ment and Con trol Sys tem (EMCS) which is
used to con trol the in door en vi ron ment of com mer cial, in sti tu tional and resi den tial build ings.
The T3000 meas ures the physi cal con di tions in the build ing such as tem pera ture, hu mid ity,
pres sure, cur rent, volt age, and status.
```

Putting that in front of a reader would be worse than not publishing it, and repairing it automatically is not safe: merging fragments by guessing which ones belong together would silently change measurements, point names and numbers in a technical manual. A repair that is right most of the time is not good enough for a document people wire panels from.

So the manual was not converted. Instead:

- [Its structure is here](software-manual-outline.md), chapter by chapter, with page numbers — enough to find what you need in the PDF
- The PDF is linked from the [opening page](00-hub.md), unmodified
- Where the same material exists in a readable form, this site links to that instead

## What *was* converted

The 50-page Installation and Technical Manual from the same folder extracts cleanly, so it was converted in full:

- [Hardware installation](hardware-installation.md)
- [Software installation](software-installation.md)
- [Networking controllers](networking.md)
- [Appendices](appendix.md)

The two Raspberry Pi Compute Module documents also extract cleanly and were converted:

- [Flashing a Raspberry Pi Compute Module](rpi-compute-module-flashing.md)
- [Backing up a Raspberry Pi Compute Module](rpi-compute-module-backup.md)

## The one character that had to be fixed

The technical manual prints bullets in a font whose character does not map to Unicode; it extracts as `ü` (U+00FC), 116 times. Those became `-`. The extraction also broke words across lines with a hyphen (`in -` / `put`), which was rejoined. Nothing else was altered: the sentences, the numbers, the point counts and the part numbers are the manual's.

## If the software manual ever needs to be readable

The 217-page `WindowsVersionSoftwareManualRev3.PDF` sits beside it in the repository, is a different typesetting, and may not have the same defect. It was not converted here because it is a later edition of the same material that is already published as the current T3000 manual, and adding 217 pages of a third edition would duplicate more than it would add. It is worth a pass if anyone needs the 2016 wording specifically.

## T3000 Controller

The T3000 Controller is a multi-user, stand alone DDC panel with full communications capabilities. The T3000 can be used either stand alone or in a multiple network system. Multiple communication ports allow the T3000 to simultaneously operate on a network, host sub networks, and to communicate to local and remote operators. Up to 128 Input/Output points may be controlled directly by the T3000 through the use of universal Input and Output Cards. The T3000 is expandable to 4 groups of 128 points to a maximum of 512 points on each panel. The number of points on a T3000 is normally limited to 128 and occasionally to 256 points because wiring such large number of points to one location is impractical. Figure 1 shows the construction of the T3000 Controller, with the optional cards. Since the T3000 is a PC based controller, it can easily support with ease options such as internal modem, Ethernet, and serial communication cards (if it is desired to have up to 4 COM ports).

*Figure 1: T3000 Controller construction*

### Data Acquisition Card

The data acquisition card (DAQ) shown in Figure 2 has a 12 bit A/D converter which converts the analog signals to digital signals. The digital signals are processed by the CPU providing real-time readings for the inputs and outputs. A 50 pin ribbon cable carries the signals between the DAQ and the connector card providing I/O control at the input and output card.

The DAQ card uses address jumpers to define which DAQ number it is in the event that multiple DAQ are needed on a single T3000 Controller. The T3000 supports 4 DAQ cards providing a total of 516 I/O points. Usually, the T3000 I/O configuration is limited to 1 DAQ card (128 I/O points) because wiring large numbers of points to one location is not normally feasible.

The card has 2 LEDs which indicate power and activity status. Should these LEDs go off, or unusual I/O is experienced, turn off the power to the T3000. Ensure that the DAQ card firmly installed in the motherboard and the 50 pin ribbon cable is well connected at both ends.

*Figure 2: Data aquisition card with 12 bit A/D converter.*

### Connector Card

The connector card has eight (8)I/O ports which act as interface between the I/O cards and the DAC card. Figure 3 shows the numerical order of the ports. Note that port 1 is the leftmost port, nearest to the floppy drive, and the port numbers increase from left to right. Port 5 is located on the second row right under port 1, and port 8 is the rightmost bottom port.

Each port is software configured as either an input or an output port. If no I/O cards are present on a particular port, that port should be disabled from the software. It is important to track the numerical order of the ports because the I/O point addressing starts from the lowest port to the highest port. If a port has been disabled, the I/O addressing will start or continue on the next configured port.

For example, if the system requires two T3-IN16 cards, and three T3-OUT16 cards, the first row can be input ports (1-4), and the second row is output ports (5-8).

Configure the software ports 1 and 2 as input ports, and ports 5,6,7 as output ports.

Ports 3, 4, and 8 should be disabled. As a result, port 1 will have inputs 1-16, and port 2 will have inputs 17-32. Ports 5, 6, and 7 will have outputs 1-16, 17-32, 33-48 respectively (see software configuration section 2.11).

*Figure 3: Conector card I/O port addressing.*

### T3-Netcard

The T3-Netcard allows the T3000 to communicate with other T3000 controllers or PCs on a RS-485 network at a maximum speed of 58600 bps. The card converts the RS-232 signal into an RS-485 signal and vice versa. Figure 4 shows how to set-up and install the T3-Netcard. The card has three RS-232 input connectors for different types of motherboard serial port connector configurations. There are two RS-485 output connectors which allow multiple controllers to join the network( see figures in section 3). Any of the two RS-485 outputs can be used since they are wired in parallel.

*Figure 4: construction and installation of the T3-Netcard on the T3000.*

The EOL (End OF Line) jumpers configuration consist of enabling resistors which prevent communication signals from bouncing once they reach the physical end of a network. Insert the jumpers if the panel is located at the physical end of a network.

- Connect the input and output.
- Apply power from the PC power supply (5 Vdc). Only the Rx (Receive) LED should be on.
- Configure the COM port as RS-485, 19200 bps in the T3000 Software(section 2.1.1).
- If both LEDs are on when powered up, there's a conflict with the RS-232 input.
The user should try the other alternate inputs. During normal operation, communication with other panels is present, the Tx (Transmit) and the Cx (receive) will blink alternately.

### Internal Modem

The modem allows remote monitoring of the controlled system under control, and has numeric paging capability in the event of an alarm.

- Configure (i.e. assign a communication port) the internal modem as COM3, IRQ 5.
Depending on the model, the internal modem can be configured either using software or using jumpers on the modem card as shown in Figure 5.

- Configure the modem's COM port in the T3000 software, as COM3, IRQ 5 (see Section 2.1.1). Then “Ok” is pressed, the T3000 operating system will display the initialization process and indicate if the communication with the modem has been successful.
*Figure 5: Internal modem with COM, and IRQ jumpers.*

## T3000 MINI 64

The MINI 64 is a stand alone Micro-processor based controller designed to control HVAC equipment as well as devices operating on the BacNet. It supports up to 4 universal I/O cards (T3-IN16, T3-OUT16, T3-8IN/8OUT). The I/O cards can be used in any configuration to meet the site's specific requirements of inputs and outputs.

Two communication ports are provided with the MINI 64. The ports are user definable via software and jumper settings. The factory setting of the COM ports are as follows:

COM1 as RS-485, COM2 as RS-232.

The MINI 64 has a flash memory of 256 Kb which provide permanent storage for the firmware, and panel program. A static RAM of 128 Kb is shared between the variables, groups, monitors, etc. The Flash memory technology allows the user to upgrade the firmware through software without the requirement to remove any EPROM chips. With no chips to remove, the firmware can be updated remotely via network or modem. Every MINI 64 comes with a real-time clock. The panel with the lowest address (panel number) will share the time to other panels as reference. The built-in capacitor can provide power to hold the program in the static RAM up to 72 hours in the event of power failure. As an extra safety measure, the MINI 64 is programmed to save the contents in the static RAM every 8 hours. Figure 9 shows the construction of the MINI 64.

### I/O Port Configuration

The MINI 64 has four (4)I/O port to support the universal T3-IN16 (16 input), T3-OUT16 (16 output)card, and the T3-IN8/OUT8 (8 input/8output) for a total of 64 points. Figure 9 shows the order of the ports. Port 1 is the lowest port, and the port numbers increases from bottom to top. Port 4 is the highest port.

Upon power up, the MINI 64 recognizes the ports that have I/O cards and automatically configures the total number of inputs and outputs available. If no I/O cards are present on a particular port, the I/O point addressing will start or continue on the next configured port.

Consider the following example:

Port 1: one T3-IN16 card

Port 2: one T3-OUT16 card

Port 3: one T3-OUT16 card

Port 4: one T3-IN8/OUT8 card The MINI 64 will automatically recognize that there are in total, 24 inputs (16+8) and 40 outputs (16+16+8). Port 1 will have input 1-16, port 2 will have output 1-16, port 3 will have output 17-32, and port 4 will have input 17-24 and output 33-40.

*Figure 9: T3000 MINI 64 layout.*

If port 3 was empty, there will be a total of 24 inputs, and 24 outputs. Port 1 will have input 1-16, port 2 will have output 1-16, port 3 is ignored, and port 4 will have input 17-24 and output 17-24.

A network consists of 2 controllers through hundreds of controllers. This section describes the set up of a basic network which can be as simple as an operator Workstation (OWS) with one controller, to a larger network with multiple segments.

The T3000, MINI 64, and MINI 16 controllers can be networked to 32 panels using RS-485 on one segment. A segment is a physical media that connect a predetermined number of panels together to form a network. Multiple segments can be connected together to form a larger network. The controller that connects to two different segment are called ROUTER controllers. If more controllers are required, extra network segments are required. The T3000 software can support 32 segments of 32 panels for a total of 1024 panels.

During the network planning stage, the designer must determine what type of panels, how many panels, how long will is the network, and how many network segments. If Ethernet is desired, consider the physical length limitation.

title: "Flashing a Raspberry Pi Compute Module"
order: 80
---

How to write a Linux image onto a Compute Module from a Windows PC. This is the procedure used for the T3 Router, which runs on a Compute Module.

You need: a Compute Module, a Compute Module IO Board (CMIO), two micro USB cables, and the Raspberry Pi Windows installer that provides the drivers and `RPiBoot.exe`.

## Put the module in flash mode

1. Download and run the Windows installer to install the drivers and boot tool.
2. Insert the Compute Module into the SODIMM connector of the Compute Module IO Board (CMIO).
3. Plug your host PC USB into the CMIO USB SLAVE port, making sure J4 is set to the USB Slave position.

The instructions were written against a Compute Module IO Board v3.0, and the IO boards are cross compatible with newer and older Compute Modules — a v1.2 board works with both 1.1 and 3+ modules.

4. Apply power to the CMIO board. Windows should now find the hardware and install the driver.
5. Once the driver installation is complete, run the `RPiBoot.exe` tool that was previously installed.
6. After a few seconds, the Compute Module eMMC will pop up under Windows as a disk (USB mass storage device).

## Write the image

The instructions use Balena Etcher; download the install or portable version and run it.

1. Click **Select image** and choose the image file — in this case the most recent Raspbian Stretch lite image.
2. Click **Select Drive** and choose the Compute Module from the list of drives.
3. Click **Flash** and wait for the write to finish.
4. After validation completes, close Etcher and follow the install procedure below.

Unplug the Compute Module from the computer and proceed to the Raspbian install procedure.

## Install a minimal Raspbian

This is a guide to installing the minimum needed for a Raspberry Pi Lite install that can run a desktop and a command line, without the extra software a standard desktop install brings. It is written for Compute Modules but works on a standard Raspberry Pi too.

To work with the Compute Module on the CMIO board, or a Temco T3 Router, as a standalone system, an HDMI display must be connected to the HDMI output of whichever board you are using. On the CMIO board a USB hub is needed to connect a Wi-Fi dongle or USB-to-LAN adapter, a keyboard and a mouse. The T3 Router provides three USB ports, so a hub is usually unnecessary.

After the system has booted and you are logged in — the default Raspberry Pi user is `pi`, password `raspberry` — open the configuration tool:

```sh
sudo raspi-config
```

### Network

Select **Network Options**, then Wi-Fi. On a new installation it first asks for your country, to set the available Wi-Fi channels, then prompts for the SSID and password.

To run the system headless and reach it over SSH, all you need is a Wi-Fi or USB-to-LAN adapter. If Wi-Fi is used, configure it first by editing the configuration file on the rootfs partition. Connect the IO board in slave mode to a computer and edit:

```sh
sudo nano /etc/wpa_supplicant/wpa_supplicant.conf
```

Add, on either Linux or Windows:

```
network={ ssid="testing" psk="testingPassword" }
```

Replace `testing` with your router's SSID and `testingPassword` with your Wi-Fi password, save the file and disconnect the IO board from the computer.

### Boot and enable SSH

Set the J4 jumper to the USB Slave position. Connect the CMIO board to HDMI, keyboard and mouse, and to a network through a USB-to-LAN adapter or a compatible USB Wi-Fi adapter. Boot the board by connecting a micro USB cable to the power input only.

```sh
sudo raspi-config
```

Select **Interfacing Options**, and enable SSH — and SPI, which the T3 Router uses.

To enable SSH on a headless system instead, create a file named `ssh` on the boot partition of the Compute Module from a Linux or Windows computer.

### Locale, time zone and keyboard

Set these in the same tool with **Localization Options**. When everything is configured, exit the tool by tabbing to **Finish**, then update the system:

```sh
sudo apt update
sudo apt upgrade
sudo apt dist-upgrade
```

Clean the package cache to free space, and reboot before installing the desktop environment:

```sh
sudo apt clean
sudo reboot
```

### Desktop environment

Install LXDE without the recommended extras:

```sh
sudo apt install --no-install-recommends xserver-xorg
sudo apt install --no-install-recommends xinit
sudo apt install lxde-core lxappearance
sudo apt install lightdm
sudo reboot
```

The system boots into the desktop. After logging in again, disable the desktop from starting on boot:

```sh
sudo raspi-config
```

Under **Boot Options** you choose whether the system boots to desktop or command line.

### Browser

```sh
sudo apt-get install -y rpi-chromium-mods
sudo apt-get install -y python-sense-emu python3-sense-emu
```

### Mono, for the T3000 GUI

Import the Mono repository by following the official distribution instructions on the Mono project website, then:

```sh
sudo apt install apt-transport-https dirmngr gnupg ca-certificates
sudo apt-key adv --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys 3FA7E0328081BFF6A14DA29AA6A19B38D3D831EF
echo "deb https://download.mono-project.com/repo/debian stable-raspbianstretch main" | sudo tee /etc/apt/sources.list.d/mono-official-stable.list
sudo apt update
```

title: "Backing up a Raspberry Pi Compute Module"
order: 90
---

Installing several Compute Modules from scratch takes a long time. This is how to take an image of one that already works the way you want, then shrink it so it fits on a smaller module and restores quickly.

These instructions cover backup and shrinking of a Raspbian OS. They may work with other Raspberry Pi operating systems; they are known not to work with Noobs.

You need a Compute Module IO Board — the same board used to flash the module — and Win32 Disk Imager, which makes a byte-for-byte copy of the module.

If you have not flashed a module before, read [Flashing a Raspberry Pi Compute Module](rpi-compute-module-flashing.md) first.

## Connect the module as a disk

Once the Compute Module is installed and configured, shut it down properly:

```sh
sudo shutdown -h now
```

Then disconnect power from the IO board and set the J4 (USB Slave/Boot Enable) jumper to the USB Slave position. Connect a micro USB cable to the USB Slave port of the module and to your PC, then a second micro USB cable to the Power In port.

When power is connected, Windows should find the hardware and install the driver. Once the installation is complete, run the `RPiBoot.exe` tool. Its command window closes by itself when it has finished, and the Compute Module eMMC appears under Windows as a disk.

If a dialog box offers to format the disk — press Cancel.

## Read the image

In slave mode two drives appear: one is the boot partition, the other the data partition.

1. Run Win32 Disk Imager.
2. Click the folder icon beside the **Image File** box, choose where to save the image, and give it a name.
3. Select one of the two Compute Module drives from the **Device** dropdown.
4. Click **Read** and wait.

A 4 GB module finishes quickly; a 32 GB module takes a considerable amount of time.

The backup file is the size of the module's flash, not of the data on it — a 4 GB module gives a 4 GB image, a 32 GB module a 32 GB image. The next step is to shrink it, which saves space and makes restoring faster.

## Shrink the image

This can be done directly on the Compute Module with a keyboard, mouse and monitor, though a USB hub will be necessary. The image is too large to keep on the module, so it must be copied to a USB thumb drive or hard drive whose file system can hold a file that size and that Raspbian can read. NTFS is the easiest choice, as both Windows and Linux support it; writing to an NTFS drive from Raspbian needs one package:

```sh
sudo apt-get install ntfs-3g
```

Then reboot:

```sh
sudo reboot
```

The remaining steps are the same on a Linux PC or on the module. Connect the drive holding the image, and install the PiShrink script:

```sh
wget https://raw.githubusercontent.com/Drewsif/PiShrink/master/pishrink.sh
chmod +x pishrink.sh
sudo mv pishrink.sh /usr/local/bin
```

Start the shrinking process:

```sh
sudo pishrink.sh -s imagefile.img newimagefile.img
```

`imagefile` is the name of the image and `newimagefile` the name of the shrunk one. With `-s` the script skips the auto-expanding step. Given a name for the new file, it works on a copy and leaves the original alone — you need enough free space for a full copy to use that option. Without a second name it shrinks the file in place:

```sh
sudo pishrink.sh -s imagefile.img
```

The shrunk image can be written to any Compute Module with the same or larger memory than the one it came from. On first boot the OS expands the file system to the full size of the module's memory. To write the image, follow [Flashing a Raspberry Pi Compute Module](rpi-compute-module-flashing.md).

Two sheets in `Documentation/Schematics` are the only surviving board drawings for the T3-BB controller:

| File | Sheet | Size |
| --- | --- | --- |
| `T3BB_top_rev27.pdf` | Top copper, revision 27 | 111 KB |
| `T3BB_bot_rev28_1.pdf` | Bottom copper, revision 28.1 | 326 KB |

Both are in the [T3000_CrossPlatform repository](https://github.com/temcocontrols/T3000_CrossPlatform/tree/master/Documentation/Schematics).

## What they are for

They are the fabrication drawings — copper layers, not a wiring diagram. Read them when you need to identify a component position, check a revision difference between 27 and 28.1, or confirm how a terminal block is routed. For how a panel is wired and addressed, the [installation chapter](hardware-installation.md) is the more useful document.

## Revision differences

Revision 27 and revision 28.1 are two different boards, not two layers of one. The top sheet is 27 and the bottom sheet is 28.1, so the pair does not describe a single board — each sheet belongs to the revision in its name. If you are working on a specific unit, find which revision it is before using either sheet.

## Missing drawings

The folder contains no schematic for the T3000 main panel, the DAQ card, the connector card or the T3-Netcard, even though the technical manual describes all of them in detail. The T3-Nano board drawing that does survive is archived as `T3-Nano_REV7_1_ALL.zip` inside the controller firmware repository, and the Zigbee radio drawing is `SCHEMATIC1 _ Zigbee_TI_2591_SMA_rev1.pdf` in the Tstat8-T3-controllers repository.
